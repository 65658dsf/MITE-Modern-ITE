# MITE: Modern ITE

开发署名：**NingMeng123**。Minecraft **1.21.1**，NeoForge **21.1.259**，模组 ID `modern_ite`。

本工程把旧 **MITE-ITE 2.0.28** 与 **Extreme LH 0.6.6** 的移植内容放入同一个拓展模组。运行时需要带扩展接口的 **MITE: Modern 0.1.9**。旧版 ITE 和极难 JAR 只作为本地规则、资源证据，不放入游戏或发布包。

## 内容对照

| 来源内容 | 当前本体状态 | 本拓展的处理 |
|---|---|---|
| 振金材料、工具、护甲、盾、弓、工作台、铁砧 | 已有 | 复用 `mite` 物品身份和既有配方、品质、成长 |
| 极难注册的 44 个生物身份 | 尚缺对应完整身份 | 注册到 `modern_ite`，保留各自技能和保存状态 |
| 僵尸领主、流浪女巫、猪人领主、湮灭骷髅 | 父 ITE 的实际依赖 | 与 44 个极难条目一起移植，共 48 个生物身份 |
| 普通怪物、龙、凋零和地元素的有效强化 | 本体已有基础行为和按日成长 | 补来源差异，通用日期成长仍由本体负责 |
| 血月、蓝月、丰收月、月晕和刷怪额度 | 本体已有日历与刷怪器 | 通过同一个扩展策略入口使用本次选定规则 |

| 振金熔炉、振金私人箱、烈焰煤粉和钻石碎块 | 尚缺 | 新增热量五熔炉、原生容器和物品 |

## 已选规则

| 项目 | 最终规则 |
|---|---|
| 血月 | 128 天前每 32 天；之后每 16 天，128 当天蓝月优先 |
| 蓝月 / 月晕 | 蓝月只在第 128 天；月晕只在第 120 天 |
| 丰收月 | 每次血月前 3 天 |
| 怪物装备进阶 | 按历史最高日期累计新日历血月数；208 天艾德曼主档，224 天振金主档 |
| 已有怪物 | 不重抽装备；保留日期成长、附魔、掉落和第 97 天永久入侵 |
| 刷怪额度 | `floor(50 × 有效区块数 / 128) + max(100, 主世界当前日期)`；血月三倍、深区再两倍；深浅分别计数 |
| 血月尝试 | 每个候选区块 6 轮，每轮 8 次；保留距离、群组、碰撞和生成事件检查 |
| 玩家等级 | 无限升级 |
| 基础生命 | `clamp(6 + 2 × floor(max(等级, 0) / 5), 6, 60)` |
| 生命宝石 | 四件护甲分别取最高阶之和，最多加 24 点 |
| 日期生命门槛 | 历史最高日 96 前 20，96 起 30，128 起 40，170 起解除日期限制 |
| 最终生命 | `min(日期门槛, 等级基础生命 + 生命宝石)`；135 级加四件六阶生命宝石为 84 点，即 42 颗心 |
| 提高 / 降低上限 | 提高不回血；卸装使上限下降时截断多余生命 |
| 饱食与营养 | 最多 20；营养宝石只补低等级容量 |
| 其他已解决冲突 | 保留本体作物速度、正常白昼、附魔维修入口和基础矿物平衡 |

## 构建

使用 Java 21，在本目录执行：

```powershell
./gradlew build
```

默认编译、运行依赖 `../miteto1.21.1neoforge/build/libs/mite-0.1.9.jar`，可通过 `-PmiteJar=绝对路径` 指定。基础模组通过普通外部依赖加载，不嵌入拓展 JAR。

```powershell
./gradlew test
./gradlew runGameTestServer
./gradlew runClient -PmodernIteClientAudit=true
```

最后一条仅在独立 `run-client` 目录执行自动客户端检查，不连接服务器或加载存档，检查后退出该实例。测试类只在开发源集，不进入发布 JAR。

资源复现脚本为 `tools/generate_gear_assets.py` 和 `tools/generate_content.py`，使用本地参考 JAR。素材原路径和 SHA-256 记录在 `modern_ite/content-provenance.json`；本次现代配方适配与资源复用也写在其中。
