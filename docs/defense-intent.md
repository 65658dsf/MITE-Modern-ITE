# 持盾怪物的攻击意图与主动防御

维护者：NingMeng123。

普通近战持盾怪物和持铁门的僵尸盗贼共用服务端 `DefenseIntent`。明确威胁触发举盾，不再依赖普通盾原来的 55% 随机尝试。防御焦点独立于仇恨目标；可见的其他生存玩家也会被识别。只改变防御决策，不增加怪物持盾生成概率，不改变伤害、耐久、盾牌材质或破防规则。

## 威胁信号

| 信号 | 规则 |
|---|---|
| 持械逼近 | 6 格内，玩家水平朝向偏差不超过 60°，自身朝怪物移动至少 0.03 格/tick，连续观察 2 tick |
| 近战戒备 | 战斗武器、面向怪物，进入本体真实武器攻击距离加 0.75 格的预警范围 |
| 挥击 | 预警范围内，战斗武器挥击射线指向怪物身体，且未被方块阻挡 |
| 近期攻击 | 最近 20 tick 对怪物发起过未取消的真实攻击，包括被盾挡住的攻击尝试 |
| 远程瞄准 | 32 格内拉弓、装填弩、持已装填弩或蓄力三叉戟，水平偏差不超过 10°、垂直允许 25°，连续观察 2 tick |
| 弹体来袭 | 32 格内有效玩家发射的箭或三叉戟，按原生重力和阻力预测未来 12 tick，将进入怪物碰撞箱外扩 0.3 格的范围 |

玩家意图需要视线。来袭弹体以弹体本身可见、飞行途中无遮挡为准，不要求射手仍在视野内。停地、远离、擦身、穿透、自己或盟友发射的箭均不触发；死亡、创造、旁观及盟友玩家被排除。空手路过、持弓未瞄准、普通农具挖掘不算攻击准备，空手或工具发起的真实攻击仍可形成短暂警戒。

接近速度来自服务器逐 tick 位置变化，不使用玩家可能陈旧的客户端速度。跨维度、缺失连续观测或单 tick 超过 4 格的位移会重置速度观测；每个持盾或持门怪物每 tick 最多扫描一次。

## 防御窗口与方向

普通盾沿用 18～30 tick 的举盾总窗口（含原生 5 tick 起手），结束后固定进入 24～40 tick 的休息窗口。铁门沿用 5 tick 起手、30 tick 有效格挡、30 tick 休息，正面斧击仍产生 60 tick 破防。普通盾的斧破防和累计格挡耗尽沿用本体共享冷却。

松弓或结束挥击不会立即取消已经开始的防御窗口；新威胁不会无限续杯，也不能绕过休息或破防。正在进行的怪物攻击前摇和恢复期不会被举盾打断，丢失所需装备、盾被禁用或死亡会结束防御。

铁门在实体 AI 执行前决定本帧是否防御，已开始的攻击恢复结束后才允许起门，避免近战连续续接导致没有防御机会。原有能力入口仍保留，同一实体 tick 的前后入口只推进一次防御计时。

来箭按命中时间优先；近战挥击或近期攻击优先于普通戒备。同级威胁保留已有焦点，另一支箭至少提前 2 tick 到达时才抢占焦点。防御非仇恨目标时停止导航和主动水平移动输入，保留原有击退等实际速度；放盾后原近战追击继续运行。

服务端在移动控制之后、原生视线控制之前提交防御朝向，头部每 tick 最多转 25°。服务端和客户端都让身体每 tick 最多转 15°，避免原生移动身体控制突然覆盖朝向。普通盾仍按原生头部正面判断，铁门仍按真实身体前方 120° 判断；威胁方向不会直接替代实际格挡方向，因此背后突袭仍可能命中。

## 验证入口

纯规则测试为 `DefenseIntentRulesTest`，真实服务端测试为 `DefenseIntentGameTests` 和 `DoorGuardGameTests`。客户端使用 `modernIteDefenseAudit=true`，在独立 `run-defense-audit` 中创建一次性世界，执行真实客户端 tick、普通盾原生同步数据和 GPU 姿态负对照；不会接入已有世界或多人服务器。

本轮独立构建目录为 `build/defense-intent-build`，冻结本体依赖为 `build/verification/defense-intent/mite-0.2.0.jar`。完整日志和客户端报告保存在 `build/verification/defense-intent/`；本轮最终结果见 [验收记录](verification.md)。
